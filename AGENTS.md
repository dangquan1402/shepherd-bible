# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- The app is **Pasture** (renamed from Shepherd on 2026-10-06; App Store name "Pasture: Daily Bible Path"). Every user-visible string, the wordmark and the StoreKit display names say Pasture. The internal identifiers deliberately keep Shepherd: the Swift module, targets and folders, `Shepherd.xcodeproj`, the `.pen` file names, the bundle id and product ids `com.dangvietquan.shepherd*`, and the repo name. Never rename them. `ShepherdTests/testUserVisibleNameIsPasture` guards the display name and the StoreKit names.
- Design lives in `design/`: `shepherd.lib.pen` (tokens + components), `screens/shepherd.pen` (imports it as alias `I`), PNG exports, and the spec in `design/README.md`. The README's token, component, frame and sample-content sections are generated: run `python3 design/tools/readme_tables.py` after changing a `.pen`.
- Edit `.pen` files only through Pencil (app, MCP, or headless `pen interactive` with a safe-save that checks `list_libraries()` is ok). Never hand-edit the JSON; a broken library link or a renamed variable silently flattens token bindings.
- Every top-level screen frame must set `theme: {"I:mode": "light"|"dark"}`, or library bindings render black.
- Release (TestFlight): `tools/archive.sh <build-number>` archives, exports and runs `tools/verify_ipa.sh` (manual signing, team 6KH82C884Q; each target names its own profile in `project.yml` Release: "Shepherd AppStore Profile" for the app, "Shepherd Widgets AppStore Profile" for `com.dangvietquan.shepherd.widgets`); bump the build number each upload. App and widget share App Group `group.com.dangvietquan.shepherd`: set entitlements only through `project.yml` `entitlements.properties` (xcodegen rewrites the `.entitlements` files on every generate). Call asc only as `asc --profile LittleRed ...` (app 6819303372); never `asc auth switch`, never another team's profile.
- Scripture, lesson and quiz text in designs must come verbatim from `Shepherd/Resources/Content/*.json` (WEB). Evergreen is the brand and means go/right; clay is quiz 'not quite'; red is destructive only; sunflower is joy only.
- Bible text (`web.json`, WEB `engwebp`) is generated by `tools/bible/build_web.py` from a SHA-256-pinned eBible zip; never hand-edit it (the "World English Bible" name is only allowed for unchanged text, punctuation included). Lesson content (`paths.json`) must pass `python3 -I tools/content/validate_content.py` (`--release` also rejects `draft` paths) and `python3 -I -m unittest discover -s tools/content`; every quiz question needs an `answerRef` proof verse among the lesson's `verseRefs`. Lesson ids are global progress keys: never rename one. The app shows lesson text through `LessonText` (curly quotes at display time, the `**Reflection:**` paragraph as a heading), so keep straight quotes in the JSON. Write lessons to `docs/content/STYLE.md`; `python3 -I tools/content/content_summary.py --lessons` gives the review table.
- `ShepherdTests/StoreKitTests` hangs in a fresh simulator clone (`[SKTestSession] Error saving configuration file: SKInternalErrorDomain Code=3`, then the test never returns); run the other suites with `-only-testing:` per class (`ContentTests`, `ShepherdTests`, `ReminderTests`, `ReviewPromptTests`, `StreakFreezeTests`) when it does. On iOS 26 StoreKit reports the `P1W` trial as 7 days, so check the period's length, not its unit.
- UI tests: the shared scheme sets `SHOT_DIR` to `docs/screenshots`, so a run overwrites committed screenshots unless you pass `TEST_RUNNER_SHOT_DIR=<scratch dir>` to xcodebuild. DEBUG launch args `-uitestCompleted <path[:n]|lessonId,...>` and `-uitestPremium` seed progress and Premium (see `RootView.applyUITestState`); `-uitestJournalAuth yes,no,...` answers the journal's Face ID/passcode checks in turn (`JournalAuthService`). Finishing a lesson now opens the optional reflection step after Lesson Complete: tests that expect Today must skip it (`skipReflection` in `RealFlowUITests`). `testRealAppFullFlow*` and `testWidgetsOnHomeScreenUpdateAfterLesson` need a fresh install (`simctl uninstall` first; the widget test also needs a Home Screen without Pasture widgets, so `simctl erase` a clone): it skips the onboarding reminder step with "Not now" and taps the springboard "Allow" when it turns the daily reminder on in Settings.
- App Store listing text (en-US subtitle, keywords, promo, description) lives in `docs/store/`; `docs/store/check_listing.py` is the source and gate. Keep it in step with what ASC holds, and never claim a feature `Entitlements.swift` or the code does not have.
- Brand (Green Pastures) source of truth is `tools/brand/`: colours in `tokens.py` (`python3 tools/brand/tokens.py check-all` runs the AA gate + Swift colour usage lint; `check pasture` runs just the AA gate), the lamb in `lambgen.py` (generated, never hand-drawn). `apply_design.py` writes both into the `.pen` files and `apply_app.py` writes colour sets, `lamb_variants.json`, AppIcon, TabLamb and wordmark. The wordmark text is set in `brandart.py` `WORDMARKS`; regenerate `wordmark.json` from Baloo 2 (`google/fonts` `ofl/baloo2/Baloo2[wght].ttf`). Change a colour or the lamb there, then re-apply to both sides. The scripts need shapely and resvg_py.
